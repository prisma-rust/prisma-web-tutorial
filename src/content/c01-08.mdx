# 怎么用这套课

这套课一课只加几行代码。用法只有三条：开着代码跟着写，卡住回去查对照，写完跑一次再往下。

## 先定读法

每课按同一顺序走：先看一句话结论，再看最小示例，再看跑起来的样子，最后看练习。结论先行，机制在后，省翻页。

课程表只写标题，正文一个文件。文件名就是课编号。`src/content/curriculum.ts` 是唯一真实来源，构建自动生成编号和导航。改标题只改课程表，正文第一行是课名。

```typescript
// 课程表只写标题，编号自动推导——改标题看课程表，正文第一行看文件
type LessonSpec = string | [title: string, status: Status];
```

状态分三种：已写完、正在写、只有标题。写到哪看状态，不看文件夹。

```typescript
// 章的状态由课汇总：全写完是已写完，全只有标题是只有标题
function derive(lessons: Lesson[]): Status {
    if (lessons.every((l) => l.status === 'ready')) return 'ready';
    if (lessons.every((l) => l.status === 'planned')) return 'planned';
    return 'writing';
}
```

## 写完就跑

改一行就运行一次。出错先看行号和原因。把错改掉再继续。本地开发三条命令写在阅读器里：

```bash
npm run dev        # 本地开发：开着代码跟着写
npm run build      # 发布前：先跑一次看会不会挂
npm run preview    # 预览发布档
```

三条命令分别做什么，写在 `README.md` 里。`dev` 只为开发看改动，`build` 为发布，`preview` 为验档。

## 四仓的用法长什么样

`Hazel` 的用法是样例驱动。`Sandbox` 是样例入口，`Hazelnut` 是编辑器。改引擎先看样例能不能跑。

```bash
# Hazel 的用法：样例驱动，改引擎先看样例
premake5 gmake && make -C build/Sandbox -j # 编样例
./Sandbox/bin/Debug/Sandbox # 跑样例
```

`MonoGame` 的用法是打开就进。`Game.Run` 一调用就进主循环，更新和绘制都在 `DoUpdate` 和 `DoDraw` 里。

```bash
# MonoGame 用法：打开就进主循环
dotnet run # 进主循环
```

`Stride` 的用法是工程驱动。`Stride.Engine` 是引擎，工程按序注册组件。改引擎先看注册了哪些系统。

```bash
# Stride 用法：工程驱动，改引擎先看注册
dotnet run --project Samples/Game/Game.csproj 2>&1 | head
```

`prisma-rev` 的用法是工作区驱动。`prism-app` 是应用层，`prism-engine` 是运行时。改应用层看 `tick_sim`，改运行时看 `update`。

```bash
# prisma-rev 用法：工作区驱动，应用层看 tick_sim
cargo run -p prism-app 2>&1 | head
```

`horizon` 只作需求方：游戏入口是 `horizon-client` 的游戏，功能到那儿认。

## 四仓对照表

| 写法 | 用法 | 引擎入口 | 样例在哪 | 适合谁 |
|---|---|---|---|---|
| `Hazel` 样例驱动 | 编样例，跑样例 | `Sandbox` | 仓库根 | 先看一眼 |
| `MonoGame` 打开就进 | `dotnet run` | `Game.Run` | 框架仓 | 传统生产图 |
| `Stride` 工程驱动 | 工程按序注册 | `GameBase` | `sources/engine` | 生态大，作架构对照 |
| `prisma-rev` 工作区驱动 | `cargo run` | `prism-app` | `projects` | 本教程主线 |
| `horizon` 需求对齐 | `cargo run` | `horizon-client` | 仓库根 | 需求方 |

表上能看：`Hazel` 短但样例散，`MonoGame` 旧但直，`Stride` 全但重，`prisma-rev` 一行跑起来且工作区明文。

## 本课定谁

不是选最简单，选生产级。单人引擎的生产级用法，我定 `prisma-rev` 的工作区驱动：一行跑起来，工作区成员固定，层之间明文。

理由有三条。

一是可复现。一行跑起来之后，看输出对不对。开发档对的，发布档也对的。新手第一步就能验收。

二是结构清楚。应用层管窗口，引擎层管运行时。查东西从应用层点名，名对得上。`Hazel` 的样例散在根上，`Stride` 的系统多容易乱。

三是生产级。发布档有签名检查，版本号对得上。教学品跑通就算，生产品跑通还不能发。`prisma-rev` 把两档分开，有明文。

```rust
// 本课定案：用法的样子
fn run() {
    cargo::run(); // 一行跑起来
    check_output(); // 看输出对不对
}
```

```rust
    check_contrast(); // 卡住回去查对照
    run_once(); // 写完跑一次
}
```

```bash
# 卡住先查三处：结论、最小示例、对照
grep -n "结论" src/content/c01-01.mdx | head # 先查结论那句
npm run dev 2>&1 | head # 再查最小示例跑没跑
```

## 卡住回去查对照

每讲一个 Rust 概念，都给了 C++ 和 C# 的同功能对照。卡住先回去看对照那一段：对照代码在那一课里，看懂对照再看 Rust。

对照 C++ 教程：像先看设计再看实现。对照 C# 教程：像先看运行再看内部。Rust 这套课先结论后机制，省翻页。

:::tip{title="卡住先查哪"}
先查结论认没认错，再查最小示例跑没跑，最后查对照懂没懂。三处都对而还卡，多半是前置没补。回去补前置再回来。
:::

## 学到哪就标到哪

课学完就把课程表里那一课的状态改成已写完。改了构建才带上新页。不改，学完了页面还停在只有标题。

```typescript
// 学完就把那一课改成已写完——改了构建才带上新页
// 从未写完的 '计划' 到 '已写完'：改一字，页面就带上
type Status = 'ready' | 'writing' | 'planned';
```

## 篮子倒计时

节奏定下来，章节就能往下推。推到哪一场就记到哪一场，记到课程表里就是状态。下次开课先跑昨天那行输出，再往下推。

```bash
# 定了节奏先认号：文件名、课程表、页面标题三处对上
ls src/content/c01-*.mdx | head # 文件名就是编号
grep -n "引擎的最小闭环" src/content/curriculum.ts | head # 课程表里看标题
```

编号对上了，读到哪都不丢。编号乱了，第一步就是校正。

完成标准：节奏写在纸上，每课都留下一行可验证的结果。

:::exercise{title="动手：定你的节奏"}
给自己定每课的时间。超时就停，把卡点记下来。下一课开始前先把昨天那行输出跑一遍。节奏定下来，章节就能往下推了，推到哪一场就记到哪一场。
:::

## 四仓在同一页上

`Hazel` 的样例驱动是散的。`MonoGame` 的打开就进是直。`Stride` 的工程驱动是全的。`prisma-rev` 的工作区驱动是一行跑起来。本课往下走，只跟第四种。
