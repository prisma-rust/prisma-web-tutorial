# 依赖方向

依赖方向错了，编译会立刻报错。Rust的依赖是一条只朝一个方向走的链，环会直接拦下来。

## 依赖只能指向一边

包 `甲` 声明依赖包 `乙`，就写在 `甲` 的清单里。`乙` 不反向依赖 `甲`。这条规定写成一句话：**依赖链是单向的**。

```toml
# crates/window/Cargo.toml —— 只写自己依赖谁
[dependencies]
log = "0.4" # 用日志库，不被日志库反向引用
```

对照 C++：头文件互相包含（`甲` 包含 `乙`，`乙` 又包含 `甲`），编译器会报循环包含。C# 里两个项目互相引用，构建直接失败。Rust清单里互指就是环，同样拦住。

## 工作区里的约定

每个包的依赖都写在自己的清单里，工作区根只管成员名单。跨包写包名，跨工作区写版本。版本放在哪都有明确位置，不藏在代码里。

C++ 大项目常用子目录清单管依赖，C# 常用解决方案管项目引用。Rust把这两件事合进清单：包清单管依赖关系，工作区清单管成员名单。改依赖只改对应包的清单。

## 依赖多了先看是谁在拉

编译慢时先看依赖是谁拉进来的。用清单里的依赖树查，不要凭感觉删。删一个顶层依赖，下面可能有十几个间接依赖跟着它走。

完成标准：你能说出每个包依赖谁、谁依赖它，并指出这条链回不回头。

:::exercise{title="动手：画依赖箭头"}
打开每个包的清单，用箭头画出依赖方向。再找一条从上到下的链，看是不是有哪一步回指。出现回指就把回指那条记下来，下一次重构先拆它。
:::
