# 你要交付的东西

这套课最后交付的不是一堆零件，而是一台能跑的引擎。它有窗口，能响应输入，能画出场景，能存档，能在断电前停下。

## 交付长这样

交付分四块，缺一块都不算交付完。

**可运行**：`cargo run` 一行跑起来。`prisma-rev` 在助手仓里是 `projects/prisma` 的二进制，入口在清单里有明文。`horizon` 是 `horizon-client` 的游戏，也是工作区成员。两边都得一行跑起来。

`prisma-rev` 的根工作区成员是固定的，入口不在主工作区里。主工作区只列核心包，游戏二进制在 `projects/prisma` 的独立工作区里。`horizon` 的根工作区成员是固定的，游戏也在主工作区里。两边一行跑起来的命令都不一样，别把两个仓的命令抄混。

```bash
cargo run -p prism-app  # prisma-rev 的应用层，窗口加渲染线程从这里起
cargo run -p horizon-client # horizon 的游戏，运行的是客户端
```

**可复现**：同样的输入同样的输出，种子固定。`horizon` 用固定种子跑测试，`prisma-rev` 用快照测试和参考图兜底。种子和顺序不在代码里写死，这块就空了。

**可诊断**：日志分级，耗时能看，失败能报。`prisma-rev` 在 `debug_hud` 里收渲染统计，`horizon` 在日志里分级。日志没四件套，出事就只能猜。

**可交付**：能打包，能签名，能更新，能回滚。`prisma-rev` 有发布档脚本，`horizon` 有发布签名检查。打包后双击能跑，才算交到玩家手里。

## 手写最小示例

```rust
// 交付四块：入口串起可运行，日志串起可诊断
fn main() {
    init_log(); // 可诊断：日志初始化
    if !reproducible() { log::warn!("种子未固定"); } // 可复现：查种子
    cargo::run(); // 可运行：跑起来
}
```

对照 C++：像带安装程序的游戏，安装程序里有可运行的检查。对照 C#：像带自动更新的桌面应用，更新前能回滚。Rust 这套课最后也要走完这条路。

## 不交付什么

交付不包括编辑器本身、包含测试用的二进制、带调试符号的开发档。这些是开发用的，发布版默认关。关掉的每样东西，都在发布脚本里有明文。

:::tip{title="交付是验收单"}
交付四项各有一张验收单：能跑的单子、能复现的单子、能诊断的单子、能交付的单子。单子没有，就当没交付。
:::

## 缺一块会发生什么

少可运行，读者接不到成品。少可复现，崩溃没法重放。少可诊断，故障只能猜。少可交付，成品到不了玩家手里。四块缺哪块，后面章节的着力点就不一样。

`horizon` 里响应速度的边界写在配置里，默认关。关掉的东西回报率低，开了才算交付里有一项。`prisma-rev` 里可选能力默认关，暖起来才进交付。两边都把默认关写在明文里。

完成标准：你能把交付四项各说一句，并指出哪一项最弱。

:::exercise{title="动手：写你的交付清单"}
把可运行、可复现、可诊断、可交付各写成可检查的一句。再给最弱的一项排期，到第几章补上。排期落到章节号，下一轮开写就从那儿开，上下文都在文档里，不用翻聊天记录。
:::

## 可运行怎么验

`cargo run` 一行跑起来之后，看输出对不对。`prisma-rev` 的输出里有渲染统计，`horizon` 的输出里有游戏启动的日志。输出里该有的那几行不在，运行就不算成。

```bash
# 可运行：跑起来看输出
cargo run 2>&1 | head # 看输出里该有的那几行在不在
```

## 可复现怎么验

同样的输入再跑一遍，输出一样不一样。`horizon` 用固定种子，种子在测试里写死。`prisma-rev` 用快照测试，输出变了测试红。种子和顺序写死，输出才稳得住。

```bash
# 可复现：种子固定，同输入同输出
cargo test 2>&1 | tail # 看测试全绿没
```

## 可诊断怎么验

日志四件套齐不齐，耗时看不看得见，失败报不报得到。`prisma-rev` 在 `debug_hud` 里收渲染统计，`horizon` 在日志里分级。切到错误级别，看警告和错误出没出。

## 可交付怎么验

打包后双击能跑，能更新，能回滚。`prisma-rev` 的发布档脚本先构建后打包，`horizon` 的发布有签名检查。签名不在，包就发不出去。

完成标准：可运行、可复现、可诊断、可交付四块，你用四条命令验完了。

:::exercise{title="动手：把四块验一遍"}
把四条命令都跑一遍，缺的那块标出来，排期到章节。排期写在清单上，下次开写就从那儿开。
:::

## 交付单子放哪

交付单子之一是清单。清单只写四块的内容。清单是人看的，构建是机器看的。清单和构建对不上，以构建为准，清单要跟着改。

清单里还记版本号。版本号变了，清单就失效，要重验。`prisma-rev` 和 `horizon` 都按版本号对单子。版本号在清单里是明文，看得见。

## 双语对照交付

C++ 的交付单子是安装程序。安装程序里带可运行的检查。C# 的交付单子是自更新的清单，更新前能回滚。Rust 的交付单子是打包后的双击运行加回滚开关。三种单子样子不同，验收一样。

完成标准：交付四块各有一张单子，单子能对上版本号。
