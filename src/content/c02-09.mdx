# 错误类型

锈语没有异常。错误直接写在返回值里，调用方必须显式处理。

## 返回值里带错误

一个可能失败的函数长这样：

```rust
// 失败时返回值里带原因，调用方必须处理
fn read_name() -> Result<String, std::io::Error> {
    Ok("engine".to_string()) // 成功时带值
}
```

用的时候被迫分两条路：

```rust
match read_name() {
    Ok(name) => println!("读到名字：{name}"),
    Err(e) => println!("读名字失败：{e}"), // 失败时带原因进日志
}
```

对照 C++：异常靠 `try` / `catch` 一跳跳走。C# 也是 `try` / `catch`。锈语没有这一跳，错误在返回值里明写，编译器逼你把失败那条路也写完。

## 当场中断只用在出乎意料处

`panic!` 表示「这里本不该发生」。初始化失败、索引越界、断言没过这类人名代码不可恢复的路径才用它。能预料到的失败走返回值。

完成标准：你能分清哪些失败会回到调用方，哪些直接中断。

:::exercise{title="动手：故意失败一次"}
让一个函数走失败那条路，看日志里带的原因。再故意触发一次中断，看输出停在哪一行。对比两种失败的区别。
:::
