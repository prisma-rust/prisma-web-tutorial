# 第一个程序

上一课装好了 `cargo`。这一课只做一件事：用 `cargo` 新建一个程序，让它打印一句话并跑起来。

## 先把四仓的第一个程序摆上桌面

`Hazel` 的第一个程序在 `Sandbox` 里。`SandboxApp.cpp` 把环境写进字符串，`Hello World` 就这么打印。编一次要先跑 `premake5`，再跑 `make`。慢，但对。

```bash
# Hazel 第一个程序：先编引擎，再编样例
premake5 gmake && make -C build/Sandbox -j
./Sandbox/bin/Debug/Sandbox # 跑样例
```

`MonoGame` 的第一个程序在 `MonoGame.Framework` 样例工程里。打开就进主循环，更新和绘制都在 `DoUpdate` 和 `DoDraw` 里。

```bash
# MonoGame 第一个程序：打开就进主循环
dotnet run --project Samples/Game/Game.csproj
```

`Stride` 的第一个程序在 `sources/engine/Stride.Engine` 的工程里，组件按序注册，时间给组件。

```bash
# Stride 第一个程序：工程驱动
ls sources/engine/Stride.Engine | head # 看引擎在哪个包
```

`prisma-rev` 的第一个程序在 `projects/prisma` 的二进制里，工作区成员固定，入口在清单里有明文。

```bash
# prisma-rev 第一个程序：工作区驱动
cargo run -p prism-app 2>&1 | head
```

`horizon` 作需求方：游戏入口是 `horizon-client`，只借功能。

## 四仓对照表

| 写法 | 第一个程序在哪 | 装一次什么 | 编一次几步 | 适合谁 |
|---|---|---|---|---|
| `Hazel` 样例驱动 | `Sandbox` | `premake5` + 编译 | 两步 | 先看一眼 |
| `MonoGame` 打开就进 | 框架样例工程 | .NET SDK | 一步 | 传统生产图 |
| `Stride` 工程驱动 | `Stride.Engine` | SDK + 拉仓 | 三步起 | 生态大，作架构对照 |

表上能看：`Hazel` 两步走，`MonoGame` 打开就进，`Stride` 重，`prisma-rev` 一行跑起来。

## 本课定谁

不是选最简单，选生产级。单人引擎的生产级第一个程序，我定 `prisma-rev` 的工作区驱动：一行跑起来，工作区成员固定。

理由有三条。

一是可运行验收。一行跑起来之后，看输出对不对。开发档对的，发布档也对的。

二是生产级。`MonoGame` 打开就进，但版本负担在 .NET SDK 上。`prisma-rev` 版本负担在清单里，对得上就在。

三是结构清楚。应用层管窗口，引擎层管运行时。查东西从应用层点名，名对得上。

```rust
// 本课定案：第一个程序的样子
fn main() {
    println!("Hello, engine"); // 往标准输出打一行
}
```

## 新建一个项目

打开终端，运行：

```bash
cargo new hello-engine
cd hello-engine
```

`cargo new` 会生成一个最简骨架：

```text
hello-engine/
  Cargo.toml       # 项目描述：名字、版本、依赖
  src/
    main.rs        # 程序入口
```

`Cargo.toml` 是 Rust 的项目清单，地位对标 C++ 的 `CMakeLists.txt`、C# 的 `.csproj`。它写明「这个程序叫什么、版本是多少、依赖哪些包」。`src/main.rs` 是真正写代码的文件。

打开 `src/main.rs`，内容只有 3 行：

```rust
// 程序入口：Rust 二进制从这里开始执行
fn main() {
    println!("Hello, engine"); // 往标准输出打一行文本
}
```

`println!` 最后那个 `!` 表示它是宏，不是普通函数。宏在编译期展开成代码。C++ 的 `std::cout`、C# 的 `Console.WriteLine` 是运行时函数，Rust 的 `println!` 是编译期展开，格式化在编译期做类型检查。

## 运行它

在项目根目录（有 `Cargo.toml` 的那一层）运行：

```bash
cargo run
```

第一次运行最慢，`cargo` 会下载依赖、编译代码、生成可执行文件。正常输出长这样：

```text
Running `target/debug/hello-engine`
Hello, engine
```

`target/debug/hello-engine` 就是编译产物（Windows 上带 `.exe`）。C++ 下对应 `g++ main.cpp -o hello && ./hello` 的两步，C# 下对应 `dotnet run` 的一步。Rust 把两步合成了一步，中间产物都放在 `target/` 里。

## 双语对照

C++ 第一个程序要手写编译：

```cpp
// C++ —— 需要 g++ 这类编译器手动编
#include <iostream> // 输入输出头文件，C++ 靠 #include 拼
int main() { // 程序入口，返回 0 表示正常退出
    std::cout << "Hello, engine\n"; // 流输出，\n 是换行
    return 0;
}
```

构建要手动两步：`g++ main.cpp -o hello` 编译，`./hello` 运行。`#include` 是文本展开，路径错了编译就停。

```bash
g++ main.cpp -o hello && ./hello
```

C# 第一个程序是一步到位：

```csharp
// C# —— dotnet run 一步跑起来
using System; // 命名空间，C# 靠 using 引入
Console.WriteLine("Hello, engine"); // 标准输出
```

```bash
dotnet run
```

Rust 侧你已经看到的 `println!("Hello, engine")`，括号里是格式化字符串，`{}` 占位会在编译期对参数做类型检查。C++ 的 `std::cout << ...` 把格式抛给了流，C# 的 `WriteLine` 靠方法重载区分。

## 读懂构建命令干了什么

`cargo run` 其实是三件事串起来：

1. 读 `Cargo.toml`，知道程序名和依赖。
2. 调 `rustc` 编译 `src/main.rs`（和依赖）到 `target/debug/`。
3. 执行编译出的二进制，把输出打印到终端。

你以后只需要记 `cargo run`、`cargo build`、`cargo test` 三个命令。`cargo build` 只编译不运行，`cargo test` 只跑测试。下面几个问题帮你确认你真的会用了。

:::exercise{title="动手：改一句并再跑"}
1. 把 `src/main.rs` 里的字符串改成你的名字，重新 `cargo run`，确认输出变了。
2. 故意删掉 `println!` 最后的分号，跑 `cargo run`，看编译器把行号和原因打印出来。记住这个错误长什么样，齿轮卡住时第一时间回去看。
3. 打开 `Cargo.toml`，把 `name = "hello-engine"` 改成别的名字，再 `cargo run`，观察 `target/debug/` 下的新二进制名字。
:::

完成标准：你能不看教程新建一个项目并跑起来。下一课就用这个骨架长出工作区和第一个引擎包。
