# 创建工作区

一个程序只有一个包时，根目录长这样：

```toml
# Cargo.toml —— 包的名字、版本和依赖
[package]
name = "hello-engine"
version = "0.1.0"
edition = "2021"
```

引擎做大后会变成好几个包：负责窗口的、负责渲染的、负责世界的。它们互相看见，但不能互相翻墙。工作区就是用来管这件事的。

## 先把四仓的工作区摆上桌面

`Hazel` 的工作区在仓库根：`premake5.lua`、`Hazel`、`Sandbox`、`Hazelnut` 四个分工。编一次先跑 `premake5`，再跑 `make`。

```bash
# Hazel 工作区：根上分三
ls | head # 看引擎、样例、编辑器在哪个包
```

`MonoGame` 的工作区更薄：`MonoGame.Framework` 是框架本体，`Tests` 是测试。打开就进主循环。

```bash
# MonoGame 工作区：框架和测试分两
ls MonoGame.Framework | head # 看框架在哪个包
```

`Stride` 的工作区在 `sources/engine` 下：`Stride.Engine` 是引擎，`Stride.Graphics` 是图形，`Stride.Games` 是游戏抽象。

```bash
# Stride 工作区：引擎、图形、游戏分三
ls sources/engine/Stride.Engine | head # 看引擎在哪个包
```

`prisma-rev` 的工作区写在根清单里，成员固定。`prism-app` 是应用层，`prism-engine` 是运行时。

`horizon` 作需求方：`horizon-client` 是游戏，工作区成员固定，只借功能。

## 四仓对照表

| 写法 | 工作区在哪 | 成员怎么写 | 依赖怎么写 | 适合谁 |
|---|---|---|---|---|
| `Hazel` 的 `premake5` | 仓库根 | 根上分三 | 手动约定 | 先看一眼 |
| `MonoGame` 的框架仓 | 框架仓根 | 框架/测试 | .NET 依赖 | 传统生产图 |
| `Stride` 的工程 | `sources/engine` 分三 | 引擎/图形/游戏 | 拉仓 | 生态大，作架构对照 |
| `prisma-rev` 的清单 | 根工作区固定成员 | 应用/引擎/渲染/平台 | 清单写死 | 本教程主线 |
| `horizon` 的清单 | 根工作区固定成员 | 游戏/世界/命令/输入 | 清单写死 | 需求方 |

表上能看：`Hazel` 根上分三，`MonoGame` 框架仓，`Stride` 工程重，`prisma-rev` 工作区固定成员。

## 本课定谁

不是选最简单，选生产级。单人引擎的工作区，我定 `prisma-rev` 的清单驱动：根只管成员名单，成员清单管自己的依赖。

理由有三条。

一是生产级。成员和依赖写死在清单里，环直接拦住。`Hazel` 那种全在根上，改个包名就断一片。

二是结构清楚。应用层管窗口，引擎层管运行时。查东西从应用层点名，名对得上。

三是可测试。层清楚了，测试也清楚。测试灌的都是包上层，不用把仓库全拖进来。

```rust
// 本课定案：工作区的样子
struct Workspace {
    members: Vec<String>, // 成员名单：只写在哪
    deps: Vec<String>, // 依赖：写在各自清单里
}
```

## 工作区解决“多个包怎么放”

在空文件夹里运行：

```bash
mkdir engine-workspace
cd engine-workspace
```

新建 `Cargo.toml`，内容只有两行：

```toml
# 工作区根：声明成员，根本身不产出二进制
[workspace]
members = ["crates/*"]
```

再建 `crates/` 子文件夹。每个子文件夹以后是一个包。根目录只管成员名单，成员之间怎么依赖写在各自包的 `Cargo.toml` 里。

对照 C++：这像 `CMake` 里写 `add_subdirectory` 管多个库。C# 里像解决方案文件把多个项目串起来。Rust 的工作区更轻：只写成员名单，不写编译顺序。

## 第一次检查工作区

成员还没建时，工作区是空的。`cargo run` 会提醒你没有可运行的包。报这个错不奇怪，先把第一个包建起来再跑。

```bash
cargo new crates/window --lib
```

`--lib` 表示这是个库包，给别人用的，不自己跑。`target/` 在工作区根统一放编译产物，不会在每个包里各放一份。C++ 需要手动约定统一输出目录，Rust 工作区默认就统一了。

完成标准：根目录有工作区清单，`crates/window` 已经是一个可构建的库包。下一课就展开第一个包。

:::exercise{title="动手：列一下成员"}
打开根 `Cargo.toml`，看看 `members` 指向了哪些文件夹。再运行 `ls crates`，确认每个成员文件夹里都有一份自己的 `Cargo.toml`。把这份名单记下来，后面加包时只改它。
:::
