# 创建工作区

一个程序只有一个包时，根目录长这样：

```toml
# Cargo.toml —— 包的名字、版本和依赖
[package]
name = "hello-engine"
version = "0.1.0"
edition = "2021"
```

引擎做大后会变成好几个包：负责窗口的、负责渲染的、负责世界的。它们互相看见，但不能互相翻墙。工作区就是用来管这件事的。

## 工作区解决“多个包怎么放”

在空文件夹里运行：

```bash
mkdir engine-workspace
cd engine-workspace
```

新建 `Cargo.toml`，内容只有两行：

```toml
# 工作区根：声明成员，根本身不产出二进制
[workspace]
members = ["crates/*"]
```

再建 `crates/` 子文件夹。每个子文件夹以后是一个包。根目录只管成员名单，成员之间怎么依赖写在各自包的 `Cargo.toml` 里。

对照 C++：这像 `CMake` 里写 `add_subdirectory` 管多个库。C# 里像解决方案文件（`.sln`）把多个项目（`.csproj`）串起来。Rust 的工作区更轻：只写成员名单，不写编译顺序。

## 第一次检查工作区

成员还没建时，工作区是空的。`cargo run` 会提醒你没有可运行的包。报这个错不奇怪，先把第一个包建起来再跑。

```bash
cargo new crates/window --lib
```

`--lib` 表示这是个库包，给别人用的，不自己跑。`target/` 在工作区根统一放编译产物，不会在每个包里各放一份。C++ 需要手动约定统一输出目录，锈语工作区默认就统一了。

完成标准：根目录有工作区清单，`crates/window` 已经是一个可构建的库包。下一课就展开第一个包。

:::exercise{title="动手：列一下成员"}
打开根 `Cargo.toml`，看看 `members` 指向了哪些文件夹。再运行 `ls crates`，确认每个成员文件夹里都有一份自己的 `Cargo.toml`。把这份名单记下来，后面加包时只改它。
:::
