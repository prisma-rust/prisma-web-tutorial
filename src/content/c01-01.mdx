# 造一台发动机

本书默认你没写过其他项目，也没装过Rust。本课只定职责边界，工具链和第一个程序在第 2 章手把手装好后立刻跑起来。后文每讲一个Rust概念，都会用 C++ 和 C# 的同功能对照说清差异。

引擎要隔开五类外部输入。

> OS 事件时序、显示器刷新率、断电、驱动重置、资源就绪时机

抽象层挡住这五类输入，游戏逻辑就可以只依赖 tick。挡不住，抖动会渗进 gameplay，变成无法复现的 bug。

渲染器是抽象层里的一层。它负责把已准备好的 tick 世界送上屏幕。

## “三只时钟”

引擎同时维护“三只时钟”。它们来源不同、用途不同、频率约束也不同。

| 时钟 | 来源 | 驱动对象 | 约束 |
|---|---|---|---|
| 真实时间 `Instant::now()` | 系统墙钟 | 超时、限帧 | 频率可变 |
| 固定 tick | 累加器按 1/60s 切片 | 物理、AI、输入 | 步长固定 |
| 显示帧 | GPU present 回调 | 渲染、插值 | 频率随显示器 |

手写 `dt = frame_end - frame_start` 并直传物理，会在 60Hz 下正常运行，在 144Hz 下让物理加速，在掉帧时让穿墙 bug 出现。原因很直接：`dt` 把显示帧的抖动带进了 tick。

解决办法是把 tick 从帧里切出来。真实时间只负责往累加器里加时长，累加器按固定步长产出 tick。

这是 `horizon` 里已经跑在生产代码中的做法，下面是手写的最小示例：

```rust ref="horizon:crates/horizon-client/src/clock.rs#L350-L371"
// 累加真实时间，按固定步长切出 tick
let ticks = timer.advance_game_time(now_ms, |d| d.max(mspt));
// “刹车片”：每帧最多补 10 个 tick，超出的时长直接丢弃
ticks.clamp(0, 10) // 防死亡螺旋的关键行，完整实现见引用跳转
```

最后一行是关键点：`ticks.clamp(0, 10)`。每帧最多补 10 个 tick，超出部分直接丢弃。`prisma-rev` 在 `tick_sim` 里用 5，`horizon` 用 10，数值随实测调整，约束本身必须存在。

## “死亡螺旋”

缺上限的累加器会把一次卡顿放大成死锁，过程是这样的。

假设一帧渲染和逻辑耗时 25ms，tick 间隔 16.6ms。

```diagram flow
真实时间 -> 累加器
累加器 -> 余量够一个 tick {diamond}
余量够一个 tick ->|够| 执行一次 tick
余量够一个 tick ->|不够| 丢弃多余时间
执行一次 tick -> 渲染插值帧
丢弃多余时间 -> 渲染插值帧
```

1. 第一帧 Accumulated 25ms，需要补 1.5 个 tick。
2. 补完 2 个 tick 后，帧处理时间涨到 40ms。
3. 第二帧需要补 2.4 个 tick，帧处理时间涨到 60ms。
4. 下一帧需要补 3.6 个 tick，时间继续上涨。

这就是“死亡螺旋”。越努力补时间，欠的越多，直到主循环跑不动。

带上限的表现完全不同。累加器在每帧截断补量，超出时长直接丢弃。丢弃 200ms 等于一次可见卡顿，继续追赶等于整个游戏失去响应。

:::warn{title="生产级铁律"}
按真实时间步进的系统必须同时定义每帧 tick 上限和超限丢弃策略。无上限的累加器是“定时炸弹”。
:::

上限要放在一眼看得到的地方。`horizon` 是 10，`prisma-rev` 的 `tick_sim` 是 5，实验室代码是 5。数字随硬件和内容调整，约束写法保持一致。

## 引擎要能报告自己的失败

真实引擎会查渲染线程是否退出。`prisma-rev` 的主循环每帧先做这件事，下面是最小示例：

```rust ref="prisma:crates/prism-app/src/app.rs#L867-L882"
// 主线程每帧自检：渲染线程死了没有
if handle.is_finished() {
    // 已退出就把失败原因收出来返回，不继续自旋空转
    return Some(shared.take_render_failure().unwrap_or("render thread exited".into()));
}
// 正常路径继续推进 tick 和渲染
```

渲染线程负责 Vulkan 上下文。初始化失败或 panic 后，主线程继续自旋会表现为白屏和 CPU 100%。这段检查把静默空转变成可报告的错误字符串，日志和 UI 都能接住。

:::tip{title="为什么这算生产级"}
生产代码为失败路径写了处理。教学代码只写happy path，生产代码要处理线程退出、设备丢失、显存不足这类少见但必然的路径。
:::
