# 造一台发动机

本书默认你没写过其他项目，也没装过 Rust。第 2 章已经装好工具链，这一课假设你能 `cargo run` 并看住输出。

## 先定评价标准

本课不按“最简单好写”选。按工业生产级选，维度只有五个：确定性、失败隔离、调度层级、线程归属、可测试性。每一仓按这五条打分。

> 确定性：同样的输入能不能得同样的输出。失败隔离：一个线程崩能不能带倒整个进程。调度层级：步进、更新、后期各管哪一段。线程归属：谁拥有渲染上下文。测试：能不能喂固定时长看步进数。

## 三仓的最小一圈

`Hazel` 的主循环在 `Application::Run` 里：

```cpp
// Hazel —— 可变步进，一帧走一遍层
void Application::Run()
{
    while (m_Running) // 直到关闭
    {
        float time = Time::GetTime();
        Timestep timestep = time - m_LastFrameTime; // 两帧间隔
        m_LastFrameTime = time;
        for (Layer* layer : m_LayerStack)
            layer->OnUpdate(timestep); // 可变步进直接灌进逻辑
    }
}
```

打分：确定性 1 分（刷新率一变行为跟着变）。失败隔离 1 分（渲染和逻辑同线程，崩了全停）。调度层级 1 分（全在 `OnUpdate` 一处）。线程归属 1 分（上下文归谁没写死）。测试 1 分（喂时长看不出步进数）。

复现 `Hazel` 的毛病很简单：在 60 赫兹上速度刚好，换 144 赫兹快一倍，加一帧 40 毫秒直接穿墙。`Sandbox` 里改两行就撞上。

```bash
# 复现 Hazel 毛病：同一份代码换刷新率看速度
g++ main.cpp -o sandbox && ./sandbox # 60 赫兹先记速度
# 换 144 赫兹再跑一次，看速度涨没涨
```

`horizon` 的时钟在 `horizon-client` 的 `clock.rs` 里。真实时间攒进虚拟时钟，切整格 tick，余数留着：

```rust ref="horizon:crates/horizon-client/src/clock.rs#L393-L413"
// 累加真实时间，切出固定 tick；每帧上限 10，超出丢弃
let ticks = timer.advance_game_time(now_ms, |d| d.max(mspt));
// “刹车片”：每帧最多补 10 个 tick，超出的时长直接丢弃
ticks.clamp(0, 10) // 完整实现点引用块去看，这行是关键
```

打分：确定性 5 分（步长固定，速率管理器决定步长）。失败隔离 3 分（时钟本身不崩，带宽够就一直跑）。调度层级 5 分（世界跑不跑、冻结、暂停各有开关）。线程归属 3 分（时钟不拥有上下文）。测试 5 分（喂毫秒看步进数）。

```rust ref="horizon:crates/horizon-client/src/clock.rs#L434-L441"
// 暂停和冻结在时钟里是对偶的两个开关
pub fn end_frame(&mut self, pause: bool) {
    self.pause = pause; // 画面暂停时残差冻住
    self.timer.update_pause_state(pause);
}
```

> 暂停是画面说了算，冻结是世界说了算。关系搞反了，暂停时屏幕还在动，冻结时画面还在算。

`prisma-rev` 的主循环在 `prism-app` 的 `tick_sim` 里。整数纳秒时钟，追赶带上限：

```rust ref="prisma:crates/prism-app/src/app.rs#L1124-L1174"
// 单步模拟与提取提交：整数纳秒时钟，追赶带上限，完整实现点引用块去看
// 先测时间，再加累加器；输入事件不决定模拟速度
let now = Instant::now(); // 瞬间：现在
let elapsed = last_frame.map(|p| now.saturating_duration_since(p)).unwrap_or(Duration::ZERO);
// 固定步长循环：整数纳秒时钟，追赶带上限
const FIXED_STEP: Duration = Duration::from_nanos(16_666_667);
let mut fixed_steps = 0;
while self.fixed_accumulator >= FIXED_STEP && fixed_steps < 8 {
    engine.fixed_update(FIXED_STEP.as_secs_f32(), &self.input); // 跑一步
    self.fixed_accumulator -= FIXED_STEP; // 用掉一格
    fixed_steps += 1;
}
```

打分：确定性 4 分（固定步长，输入不决定模拟速度）。失败隔离 5 分（渲染线程独立拥有上下文，主线程自检）。调度层级 4 分（固定步、更新、后期各一段）。线程归属 5 分（上下文归渲染线程）。测试 4 分（喂纳秒看步进数）。

主循环失败隔离长这样：

```rust ref="prisma:crates/prism-app/src/app.rs#L810-L830"
// 每帧自检：渲染线程死了就返回错误，不继续自旋
fn tick_frame() {
    if handle.is_finished() {
        return Some(failure); // 把失败原因带回去
    }
    tick_sim(true); // 然后跑一圈逻辑和提取
}
```

## 三选一的对照表

| 写法 | 确定性 | 失败隔离 | 调度层级 | 线程归属 | 测试 | 适合谁 |
|---|---|---|---|---|---|---|
| `Hazel` 可变步进 | 差，跟着帧走 | 差，同线程连坐 | 差，全在一处 | 差，没写死 | 差，看不出步进 | 先看一眼 |
| `horizon` 虚拟时钟 | 好，速率管理器 | 中，时钟不崩 | 好，冻结暂停清 | 中，不拥有上下文 | 好，喂毫秒 | 多人对战 |
| `prisma-rev` 固定累加器 | 好，固定步长 | 好，渲染线程独立 | 好，三段分工 | 好，渲染线程拥有 | 好，喂纳秒 | 本教程主线 |

表上能看：`Hazel` 短但跑到线上就飘，`horizon` 牢但绑着原版规格，`prisma-rev` 在线上和教程之间平衡。

## 本课定谁

不是选最简单，选生产级。单人引擎的生产级写法，我定 `prisma-rev` 的组合：整数纳秒时钟、固定步长、每帧上限、渲染线程独立拥有上下文、固定步/更新/后期三段。

理由有四条，都对应评价标准。

一是确定性。固定步长加上“输入不决定模拟速度”，重放才能对上。`Hazel` 那种两帧间隔灌进逻辑的写法，重放第一步就飘了。

二是失败隔离。上下文归渲染线程，主线程查它死了没。死了报原因退，不死继续跑。教学代码只写快乐路径，生产代码先写这条。

三是调度层级。固定步管物理，更新管逻辑，后期管画面。各一段，错了能定位到段。`Hazel` 全在 `OnUpdate` 一处，定位只能猜。

四是线程归属。谁拥有谁写死， ownership 清了，锁和通道才有意义。归属没写死的引擎，后面改交换链先崩。

```rust
// 本课定案：工业级时钟的样子
struct Clock {
    bank: Duration, // 累加器：攒着的余数
    step: Duration, // 步长：固定大小
    max_steps: u32, // 上限：每帧最多跑几步
}
```

三行就是全部家当。后面几课都从这三行长出去。

## 手写最小示例

```rust
// 手写最小：真实时间往累加器加时长，固定步长产出 tick
let mut bank: Duration = Duration::ZERO; // 攒着的余数
bank += elapsed; // 本帧进来多少，先加进去
while bank >= STEP {
    world::step(STEP); // 切一格出来干活
    bank -= STEP; // 用掉一格，剩下的是余数
}
```

```rust
// 刹车片：每帧最多补 8 个，超出的时长直接丢弃
let ticks = bank / STEP;
let ticks = ticks.clamp(0, 8); // 上限在看得见的地方
```

上面两段是教程主线。完整实现点引用块去看，行号不跟着变。

## 双语对照

C++ 里 `Hazel` 的同功能写法就是可变步进。到了教程这里，直接换成固定步长：

```cpp
// C++ —— 从 Hazel 的可变步进换成固定步长
void tick(float frame_dt) {
    accumulator += frame_dt; // 真实时间往累加器加
    while (accumulator >= STEP) {
        physics::step(STEP); // 固定步长干活
        accumulator -= STEP;
    }
    renderer::draw(alpha); // 画面拿余数插值
}
```

```bash
g++ main.cpp -o engine && ./engine
```

C# 里逻辑固定更新，画面按渲染帧：

```csharp
// C# —— 逻辑固定更新，画面按渲染帧
void Tick() {
    accumulator += Time.deltaTime; // 真实时间往累加器加
    while (accumulator >= Step) {
        Physics.Step(Step); // 固定步长干活
        accumulator -= Step;
    }
    Renderer.Draw(alpha); // 画面插值
}
```

```bash
dotnet run
```

三边步长都写死。写死才不会随刷新率飘。

## “死亡螺旋”先长在上限那

掉帧时如果一直追时间，越追越远。刹车那一步是上限。累加器攒多少、补多少、丢多少，后面几课细讲。

:::warn{title="先这样记住"}
增量只往累加器里加时长。逻辑只认固定步长。哪边越界，画面和逻辑就对不上了。
:::

## 跟着看的结果

这一课验收只有一个：你能说出为什么教程选了 `prisma-rev` 的写法，不选 `Hazel` 的可变步进，也不先啃 `horizon` 的虚拟时钟，以及这三仓在确定性、失败隔离、调度层级、线程归属上各差哪儿。

验收单只有四行，照着念就行：

```text
1. 逻辑只认固定步长，不认两帧间隔。
2. 累加器攒真实时间，攒够一格切一格。
3. 每帧上限看得见，超量时间直接丢。
4. 画之前先算，顺序定死。
```

四行对上了，这一课算过。下一课分名字：时长是一段长短，瞬间是一个时刻。分开，代码才不混。按名字查`固定累加器`，就是本章后面几课的活。

:::exercise{title="动手：亲手撞上毛病"}
打开任意一个演示，把刷新率从 60 改成 144，看移动速度涨没涨。再给一帧故意加 40 毫秒延迟，看角色穿墙没穿墙。记下三个时间点：60 赫兹、144 赫兹、掉帧。涨了，你就亲手撞上了这个毛病。改回来。把 60 赫兹的速度和 144 赫兹的速度各记一个数，差值就是可变步进的飘量。
:::

## 三仓在同一页上

`Hazel` 的 `Application::Run` 是可变步进，短但飘。`horizon` 的 `FixedStep::advance` 是虚拟时钟，牢但重。`prisma-rev` 的 `tick_sim` 是固定累加器，够用且可复现。本课往下走，只跟第三种。
