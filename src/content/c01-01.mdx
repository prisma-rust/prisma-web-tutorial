# 造一台发动机

本书默认你没写过其他项目，也没装过 Rust。第 2 章已经装好工具链，这一课假设你能 `cargo run` 并看住输出。

## 先把三仓的引擎主循环摆上桌面

三仓各有一种主循环。`Hazel` 是 C++ 引擎，`horizon` 是 Java 版 Minecraft 的重写，`prisma-rev` 是自研渲染器。先看顺序，再看优缺点，最后定本课的写法。

`Hazel` 的主循环在 `Application::Run` 里：

```cpp
// Hazel —— 可变步进，一帧走一遍层
void Application::Run()
{
    while (m_Running) // 直到关闭
    {
        float time = Time::GetTime();
        Timestep timestep = time - m_LastFrameTime; // 两帧间隔
        m_LastFrameTime = time;
        for (Layer* layer : m_LayerStack)
            layer->OnUpdate(timestep); // 可变步进直接灌进逻辑
    }
}
```

优点：短，一眼看完，层栈加进来只多加一行。缺点：步进跟着帧走，刷新率一变行为跟着变；两帧间隔大时逻辑被拉长，穿墙和加速是迟早的事。

复现 `Hazel` 的毛病很简单：在 60 赫兹显示器上跑起来，角色速度刚好。把显示器换成 144 赫兹，同一份代码速度快一倍。给一帧故意加 40 毫秒延迟，角色直接穿墙。这两步在 `Hazel` 的 `Sandbox` 里改两行就能撞上。

```bash
# 复现 Hazel 毛病：同一份代码换刷新率看速度
g++ main.cpp -o sandbox && ./sandbox # 60 赫兹先记速度
# 换 144 赫兹再跑一次，看速度涨没涨
```

`horizon` 的时钟在 `horizon-client` 的 `clock.rs` 里。真实时间攒进虚拟时钟，切整格 tick，余数留着：

```rust ref="horizon:crates/horizon-client/src/clock.rs#L393-L413"
// 累加真实时间，切出固定 tick；每帧上限 10，超出丢弃
let ticks = timer.advance_game_time(now_ms, |d| d.max(mspt));
// “刹车片”：每帧最多补 10 个 tick，超出的时长直接丢弃
ticks.clamp(0, 10) // 完整实现点引用块去看，这行是关键
```

优点：步长固定，逻辑可复现；上限显式，丢弃策略清楚。缺点：代码量大，虚拟时钟、残差、速率管理器三样东西要先学完；原版对齐的约束让人想简单改都改不动。

`horizon` 这套难在它和原版一对一。原版的 `DeltaTracker.Timer` 是一套浮点残差，原版的速率管理器是另一套。初学者想改一个数，改完要先回答原版为什么这么写。教程先绕开这套，学够用的那一套。

`prisma-rev` 的主循环在 `prism-app` 的 `tick_sim` 里。整数纳秒时钟，追赶带上限：

```rust ref="prisma:crates/prism-app/src/app.rs#L1124-L1174"
// 单步模拟与提取提交：整数纳秒时钟，追赶带上限，完整实现点引用块去看
// 先测时间，再加累加器；输入事件不决定模拟速度
let now = Instant::now(); // 瞬间：现在
let elapsed = last_frame.map(|p| now.saturating_duration_since(p)).unwrap_or(Duration::ZERO);
// 固定步长循环：整数纳秒时钟，追赶带上限
const FIXED_STEP: Duration = Duration::from_nanos(16_666_667);
let mut fixed_steps = 0;
while self.fixed_accumulator >= FIXED_STEP && fixed_steps < 8 {
    engine.fixed_update(FIXED_STEP.as_secs_f32(), &self.input); // 跑一步
    self.fixed_accumulator -= FIXED_STEP; // 用掉一格
    fixed_steps += 1;
}
```

优点：够用就够了。步长、累加器、上限三样写在同一处，失败路径也短。缺点：属性层面没把冻结和步进的边界写死在类型里，后面扩展要放手放脚。

`prisma-rev` 的取舍很实在：冻结状态直接在调用处传参，步进上限直接写在循环条件里。想改就改，想看就看，读完就懂。

## 三选一的对照表

| 写法 | 步长 | 上限 | 能复现 | 读懂要几步 | 适合谁 |
|---|---|---|---|---|---|
| `Hazel` 可变步进 | 跟着帧走 | 没有 | 否，换刷新率就变 | 一步 | 先看一眼 |
| `horizon` 虚拟时钟 | 固定 | 有，写死 10 | 是 | 五步起 | 照着原版对 |
| `prisma-rev` 固定累加器 | 固定 | 有，写死 8 | 是 | 两步 | 教程主线 |

表上能看：`Hazel` 短但飘，`horizon` 牢但重，`prisma-rev` 够用且可复现。本课就定 `prisma-rev` 这一列。

## 本课定谁

三选一，我选 `prisma-rev` 的写法当教程主线：整数纳秒时钟、固定步长、每帧上限。

理由有三条。

一是够用就够了。三样写在同一处，读者一次看完。`horizon` 的虚拟时钟和速率管理器是原版对齐的产物，教程先不啃那套。

二是可复现。`Hazel` 的可变步进复现不了：换一台刷新率就换一种行为。固定步长能复现，测试也好写。

三是结构清楚。累加器、步长、上限各一个名字，失败时查日志能对上。`Hazel` 那种两帧间隔灌进逻辑的写法，在教程里只当反例。

```rust
// 本课定案：存这组名字
struct Clock {
    bank: Duration, // 累加器：攒着的余数
    step: Duration, // 步长：固定大小
    max_steps: u32, // 上限：每帧最多跑几步
}
```

三行就是全部家当。后面几课都从这三行长出去。

## 手写最小示例

```rust
// 手写最小：真实时间往累加器加时长，固定步长产出 tick
let mut bank: Duration = Duration::ZERO; // 攒着的余数
bank += elapsed; // 本帧进来多少，先加进去
while bank >= STEP {
    world::step(STEP); // 切一格出来干活
    bank -= STEP; // 用掉一格，剩下的是余数
}
```

```rust
// 刹车片：每帧最多补 8 个，超出的时长直接丢弃
let ticks = bank / STEP;
let ticks = ticks.clamp(0, 8); // 上限在看得见的地方
```

上面两行是教程主线。完整实现点引用块去看，行号不跟着变。

## 双语对照

C++ 里 `Hazel` 的同功能写法就是可变步进。到了教程这里，直接换成固定步长：

```cpp
// C++ —— 从 Hazel 的可变步进换成固定步长
void tick(float frame_dt) {
    accumulator += frame_dt; // 真实时间往累加器加
    while (accumulator >= STEP) {
        physics::step(STEP); // 固定步长干活
        accumulator -= STEP;
    }
    renderer::draw(alpha); // 画面拿余数插值
}
```

```bash
g++ main.cpp -o engine && ./engine
```

C# 里逻辑固定更新，画面按渲染帧：

```csharp
// C# —— 逻辑固定更新，画面按渲染帧
void Tick() {
    accumulator += Time.deltaTime; // 真实时间往累加器加
    while (accumulator >= Step) {
        Physics.Step(Step); // 固定步长干活
        accumulator -= Step;
    }
    Renderer.Draw(alpha); // 画面插值
}
```

```bash
dotnet run
```

三边步长都写死。写死才不会随刷新率飘。

## “死亡螺旋”先长在上限那

掉帧时如果一直追时间，越追越远。刹车那一步是上限。累加器攒多少、补多少、丢多少，后面几课细讲。

:::warn{title="先这样记住"}
增量只往累加器里加时长。逻辑只认固定步长。哪边越界，画面和逻辑就对不上了。
:::

## 跟着看的结果

这一课验收只有一个：你能说出为什么教程选了 `prisma-rev` 的写法，不选 `Hazel` 的可变步进，也不先啃 `horizon` 的虚拟时钟。

验收单只有四行，照着念就行：

```text
1. 逻辑只认固定步长，不认两帧间隔。
2. 累加器攒真实时间，攒够一格切一格。
3. 每帧上限看得见，超量时间直接丢。
4. 画之前先算，顺序定死。
```

四行对上了，这一课算过。下一课分名字：时长是一段长短，瞬间是一个时刻。分开，代码才不混。按名字查`固定累加器`，就是本章后面几课的活。

## 三仓在同一页上

`Hazel` 的 `Application::Run` 是可变步进，短但飘。`horizon` 的 `FixedStep::advance` 是虚拟时钟，牢但重。`prisma-rev` 的 `tick_sim` 是固定累加器，够用且可复现。本课往下走，只跟第三种。

## 动手亲手撞一遍

把 `Hazel` 的 `Run` 路径在脑子里走一遍：两帧间隔进逻辑，刷新率一变速度一变。把 `horizon` 的 `advance` 路径走一遍：真实时间进残差，切整格，上限夹住。把 `prisma-rev` 的 `tick_sim` 路径走一遍：入口测时间，累加器攒，步长切，上限夹住。三条路走完，就知道算法和架构在纸上的差别。
