# 第一个包

包是 Rust 里最小的复用单元。一个包里有一份清单和一份到几份源文件。引擎里大到负责渲染的包、小到只管日志的包，都长同一个形状。

## 先把四仓的包摆上桌面

`Hazel` 的包地图在仓库根：`Hazel` 是引擎，`Sandbox` 是样例。查一个东西先看根目录有哪个包。

```bash
# Hazel 的包先分：引擎、样例、编辑器，查一个从引擎点名
ls | head # 看引擎在哪个包
```

`MonoGame` 的包在框架仓根：`MonoGame.Framework` 是框架本体。查一个东西先看框架在哪个包。

```bash
# MonoGame 的包先分：框架和测试，查一个从框架点名
ls MonoGame.Framework | head # 看框架在哪个包
```

`Stride` 的包在 `sources/engine` 下：`Stride.Engine` 是引擎，`Stride.Graphics` 是图形。查一个东西先看引擎在哪个包。

```bash
# Stride 的包先分：引擎、图形、游戏，查一个从引擎点名
ls sources/engine/Stride.Engine | head # 看引擎在哪个包
```

`prisma-rev` 的包在工作区清单里固定。`prism-app` 是应用层，`prism-engine` 是运行时。查一个东西先看清单在哪个包。

`horizon` 作需求方：`horizon-client` 是游戏，包固定，只借功能。

| 写法 | 包在哪 | 边界怎么写 | 能查 | 适合谁 |
|---|---|---|---|---|

## 本课定谁

不是选最简单，选生产级。单人引擎的包边界，我定 `prisma-rev` 的清单驱动：清单里声明依赖，`src` 里用包名调用。

理由有三条。

一是生产级。成员和依赖写死在清单里，环直接拦住。`Hazel` 那种全在根上，改个包名就断一片。

二是结构清楚。跨包只认公开名字，外层看不见没写公开的新名。查东西从应用层点名，名对得上。

三是可测试。层清楚了，测试也清楚。测试灌的都是包上层，不用把仓库全拖进来。

```rust
// 本课定案：包的样子
pub fn title() -> &'static str {
    "Engine Window" // 对外公开的名字从这里报
}
```

## 新建一个库包

在工作区根运行：

```bash
cargo new crates/window --lib
```

`--lib` 告诉 `cargo` 这是库包。库包不带入口函数，别人用包名的形式引用它。二进制包不加参数，自带入口。

打开 `crates/window/Cargo.toml`：

```toml
# 子包清单：名字和根清单的成员名单对上
[package]
name = "window"
version = "0.1.0"
edition = "2021"
```

打开 `crates/window/src/lib.rs`：

```rust
// 库入口：对外公开的名字都从这里往外报
pub fn title() -> &'static str {
    "Engine Window" // 返回一个固定标题
}
```

`pub` 是对外可见。放到根的 `src/main.rs` 里这样用：

```rust
// 二进制包用库包：前缀写包名
fn main() {
    println!("{}", window::title()); // 调用 window 包的函数
}
```

对照 C++：像头文件里声明、源文件里实现，别人包含头文件。对照 C#：像程序集里公开类，别人引用程序集。Rust 的 `pub` 划分公开和私有，比宏开关和访问修饰符都显式。

## 包的边界就是可见性边界

跨包引用只认 `pub`。`window::title` 能被外层看见，`lib.rs` 里没写 `pub` 的函数外层连名字都看不见。边界错了，编译器直接停下来指出行号。

完成标准：根程序能调到 `window::title` 并打印。下一课讲什么时候该把代码拆成新包。

:::exercise{title="动手：加一个私有名字"}
在 `crates/window/src/lib.rs` 里加一个不写 `pub` 的函数，在 `main.rs` 里试着调用它。运行后看编译器把哪一行拦下来。记住这个错误长什么样，它就是包边界在起作用的证据。
:::
