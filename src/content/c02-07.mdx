# 特性开关

同一个包要给不同环境交不同的代码时，用特性开关。开关描述的是「这份代码什么时候编译进来」。

## 清单里声明开关

在包的清单里写一段特性声明：

```toml
# 开启这个开关，日志就多打时间戳；不开启就只打正文
[features]
verbose = []
```

用的时候在命令行打开：

```bash
cargo run --features verbose
```

代码里用条件编译选路：

```rust
// 只在开了 verbose 时编译这一句
#[cfg(feature = "verbose")]
println!("多一条日志：tick = 42");
```

对照 C++：像 `#if VERBOSE`，宏开关在预处理阶段决定编不编。C# 像预处理符号 `#if VERBOSE`，通过项目里的常量开关。锈语的特性开关在包清单里声明，编译期选支。

## 不该用开关的地方

开关管的是环境差异，不是业务流程。业务流程变着来，用普通参数和分支。开关满天飞，组合就指数涨。

完成标准：你能说出自己包的开关管哪个环境，关掉它程序照样能跑。

:::exercise{title="动手：加一个无害开关"}
给包清单加一个空特性，在代码里只在它开启时多打一条日志。先开启跑一次，再关闭跑一次，两次差别完全在那条日志上。
:::
